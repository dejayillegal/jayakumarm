# JAYAKUMAR M — Portfolio Website

## Overview

This is a retro-futurist arcade-themed portfolio website for Jayakumar M, a Web Architect and QA Innovator. The application showcases a unique design aesthetic that merges vintage arcade terminals with futuristic minimalism, featuring a black and white color scheme with neon orange accents (#FF6B00), CRT scanline effects, and terminal-inspired typography.

The portfolio presents professional work through an interactive, visually striking interface with sections for hero introduction, about/bio, project showcase, timeline, and contact information. The design emphasizes pixel-perfect layouts, animated transitions, and a distinctive "CRT console from 2080" visual language.

## User Preferences

Preferred communication style: Simple, everyday language.

## System Architecture

### Frontend Architecture

**Framework**: React 18+ with TypeScript, using a single-page application (SPA) architecture with client-side routing via Wouter.

**Build System**: Vite is used as the build tool and development server, providing fast hot module replacement and optimized production builds. The client code is bundled separately from the server code using esbuild for the backend.

**UI Component Library**: The application uses shadcn/ui components (Radix UI primitives) configured in the "new-york" style. Components are heavily customized with a retro-arcade aesthetic through Tailwind CSS utility classes.

**Styling Approach**: Tailwind CSS with extensive custom configuration for the retro-futurist theme. CSS variables are used for theming with a dark mode-first approach. Custom utilities include scanline effects, CRT noise textures, and terminal-style animations.

**Animation Library**: Framer Motion is used for complex animations including parallax scrolling, typewriter effects, and entrance animations that align with the arcade terminal aesthetic.

**State Management**: TanStack Query (React Query) handles server state and data fetching. The application uses React hooks for local component state.

**Typography**: Google Fonts integration provides three specialized fonts: JetBrains Mono (primary monospace), Space Mono (alternative monospace), and VT323 (bitmap/pixel style for display titles).

### Backend Architecture

**Server Framework**: Express.js running on Node.js, configured to serve both API routes (prefixed with `/api`) and static assets.

**Module System**: ESM (ES Modules) is used throughout the application, as indicated by `"type": "module"` in package.json.

**Request Handling**: Custom middleware logs API requests with timing information. JSON request bodies are parsed with access to raw body data for potential webhook verification.

**Development Mode**: In development, Vite's middleware mode is integrated directly into Express for seamless HMR and asset serving. Production mode serves pre-built static files.

**Routing Strategy**: The server uses a centralized routing registration pattern where all routes are defined in `server/routes.ts` and registered with the Express app. Currently, the application appears to be primarily frontend-focused with minimal backend API surface.

### Data Storage Solutions

**Database**: PostgreSQL (via Neon serverless driver) is configured as the primary database.

**ORM**: Drizzle ORM provides type-safe database operations with schema definitions in TypeScript. Database migrations are managed through drizzle-kit.

**Schema Design**: A minimal user schema is defined with id, username, and password fields. The schema uses PostgreSQL-specific features like `gen_random_uuid()` for primary key generation.

**Storage Abstraction**: An `IStorage` interface provides CRUD methods, with a `MemStorage` in-memory implementation for development/testing. This abstraction allows switching between in-memory and database-backed storage without changing application code.

**Session Management**: `connect-pg-simple` is configured for PostgreSQL-backed session storage, though session implementation details are not fully visible in the provided code.

### External Dependencies

**UI Component Primitives**: Extensive use of Radix UI components (@radix-ui/*) for accessible, unstyled UI primitives including dialogs, dropdowns, tooltips, accordions, and form controls.

**Form Handling**: React Hook Form with @hookform/resolvers for form validation, integrated with Zod schemas generated by drizzle-zod.

**Date Utilities**: date-fns library for date manipulation and formatting.

**Carousel/Slider**: embla-carousel-react for touch-friendly carousels.

**Command Palette**: cmdk library for command menu interfaces.

**Database Connection**: @neondatabase/serverless for serverless-compatible PostgreSQL connections.

**Development Tools**: Replit-specific plugins for development experience including runtime error overlay, cartographer (code visualization), and dev banner.

**Icon Library**: Lucide React for consistent, customizable icons throughout the interface.

### Design System Specifications

The design system is documented in `design_guidelines.md` with specific requirements:

- **Color Palette**: Deep matte black backgrounds (#000000 or #0a0a0a), neon orange accents (#FF6B00), gray tones for secondary text, and lime green for special highlights
- **Typography Scale**: Monospace fonts for all body text, bitmap/pixel fonts for display titles
- **Spacing System**: Tailwind units of 4, 6, 8, 12 for pixel-perfect alignment
- **Visual Effects**: CRT scanlines, glass-pixel aesthetics with translucent overlays, glitch animations, particle effects on hover
- **Layout Grid**: Modular asymmetric composition with animated borders and subtle 3D perspective transforms
- **Section Patterns**: Each major section (Hero, About, Projects) has specific terminal-inspired formatting and animation patterns
